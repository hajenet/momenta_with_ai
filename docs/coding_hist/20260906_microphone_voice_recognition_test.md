# 연결 마이크 음성 인식 성능·노이즈 캔슬링 검토

- 작성일: 2026-09-06
- 목적: 현재 연결된 마이크의 거리별 음성 명령 인식률을 측정하고, 노이즈 캔슬링 개발 가능성을 검토한다.
- 현재 Windows 표시 장치: `Microphone (High Definition Audio Device)`
- 주의: 이 표시명만으로는 실제 마이크 제조사, 모델, 감도, 지향성, 내장 DSP 여부를 알 수 없다.

### 현재 PC에서 확인한 정보

- Windows capture endpoint: `Microphone(High Definition Audio Device)`
- PnP 상태: `OK`
- 표시 제조사: `Microsoft` (오디오 엔드포인트 제공자)
- 드라이버 버전: `10.0.19041.1`
- Hardware ID: `MMDEVAPI\\AudioEndpoints`
- DirectShow 캡처 장치: `Microphone(High Definition Audio Device)`

이 정보는 실제 마이크 캡슐의 제조사·모델이 아니라 Realtek/High Definition Audio 입력 엔드포인트 정보다. 따라서 현재 상태에서는 제조사 spec을 근거로 감도나 최대 인식 거리를 추정할 수 없다. 마이크 본체, 구매 기록, USB 장치명 또는 정확한 모델명이 추가로 필요하다.

현재 확인 가능한 것은 장치가 정상 인식되어 있고 캡처 장치로 노출된다는 점까지다. 실제 인식률은 사용자가 각 거리에서 고정 문장을 말하는 실험으로 측정해야 한다.

## 1. 거리와 데시벨 중 무엇을 측정할까?

둘 중 하나만 선택하지 말고 **거리 + 마이크 위치의 음압 레벨(dB SPL) + 주변 소음 레벨**을 함께 기록한다.

- 거리는 실제 사용 환경을 재현하는 변수다.
- dB SPL은 마이크에 도달한 목소리 크기를 비교하는 물리적 기준이다.
- 주변 소음과 목소리의 차이인 SNR(signal-to-noise ratio)이 인식 성능에 직접적인 영향을 준다.
- 같은 1m라도 말하는 사람의 음량, 방의 반사음, 컴퓨터 팬 소음에 따라 결과가 달라진다.

음성 인식률을 비교할 때는 다음 값을 기록한다.

```text
거리(m)
마이크 위치의 말소리 dB SPL
말하지 않을 때의 주변 소음 dB SPL
SNR = 말소리 dB SPL - 주변 소음 dB SPL
명령 인식 성공/실패
인식된 문장
오인식·누락·지연 시간
```

## 2. 권장 거리 시험 구간

사용자가 제시한 구간을 그대로 사용한다.

| 거리 | 시험 목적 |
|---:|---|
| 30cm | 책상 앞 근거리 기준값 |
| 50cm | 일반적인 데스크톱 사용 거리 |
| 80cm | 책상 반대편 또는 약간 떨어진 위치 |
| 1m | 방 안 대화형 사용 기준 |
| 1.5m | 소형 방·회의 공간 기준 |
| 3m | 원거리 음성 명령 가능성 확인 |
| 5m | far-field 한계 탐색 |
| 8m | 잔향·소음 영향 확인 |
| 10m | 실험적 최대 거리, 성공률보다 실패 양상 관찰 |

30cm부터 1.5m까지는 10회 이상 반복해 정량 비교하고, 3m 이상은 20회 이상 반복하는 것이 좋다. 원거리에서는 거리보다 방의 크기와 마이크 배열·지향성이 결과를 크게 바꿀 수 있다.

## 3. 시험 절차

### 고정 조건

- 같은 방, 같은 마이크 방향, 같은 PC 볼륨을 유지한다.
- 마이크 자동 게인과 Windows 음향 효과의 상태를 기록한다.
- 시험자는 매 거리마다 같은 위치를 바라보고 같은 보통 목소리로 말한다.
- 명령어 세트를 고정한다. 예: `시리`, `고고`, `고스톱`, 일반 작업 명령 5개.
- 각 명령은 거리별로 최소 10회 반복한다.
- 음성 원본은 기본 저장하지 않고, 필요할 때만 명시적으로 동의한 시험에서 저장한다.

### 측정 순서

1. 마이크를 고정하고 시험 위치를 표시한다.
2. 말하지 않는 상태에서 10초간 주변 소음 수준을 측정한다.
3. 시험자가 고정된 문장을 보통 음량으로 3회 말해 기준 음압을 기록한다.
4. 동일 거리에서 wake 명령, 전송 명령, 작업중지 명령을 각각 반복한다.
5. 성공률, 오인식률, 명령까지 걸린 시간, 잘못된 전송 여부를 기록한다.
6. 같은 거리에서 배경 소음 조건을 바꿔 반복한다.

### 권장 배경 소음 조건

```text
조용한 방
PC 팬·에어컨 동작
사람의 낮은 대화
키보드·마우스 소리
음악 또는 스피커 재생
```

## 4. 평가 지표

단순히 “문장이 얼마나 잘 받아쓰기 되었나”만 보지 않고, 이 프로젝트의 명령 흐름에 맞춰 측정한다.

| 지표 | 의미 |
|---|---|
| Wake recall | 실제로 부른 wake 별칭을 깨운 비율 |
| False wake rate | 부르지 않았는데 깨어난 횟수 |
| Command accuracy | `고고`·`고스톱`을 정확히 구분한 비율 |
| False send rate | 전송하지 않아야 할 때 전송된 비율 |
| Cancel success | `고스톱`으로 녹음·전송·작업이 중단된 비율 |
| Latency | 발화 종료부터 동작까지 걸린 시간 |
| CER/WER | 일반 문장의 글자/단어 오류율 |

특히 `False send rate`는 0에 가깝게 유지해야 한다. 인식률을 높이려고 임계값을 낮추면 실수로 Codex 작업이 전송될 수 있으므로, 전송은 보수적으로 판단한다.

## 5. 결과 기록 표준

```text
test_id,distance_m,speech_db_spl,noise_db_spl,snr_db,command,trial,recognized,success,latency_ms,error
30cm,0.30,,, ,gogo,1,,, ,
```

시험 결과는 원본 음성 대신 숫자·성공 여부·오류 유형만 저장하는 것을 기본으로 한다.

## 6. 노이즈 캔슬링 개발 가능성

개발할 수 있다. 다만 노이즈 캔슬링은 하나의 기능이 아니라 다음 DSP 단계를 조합하는 작업이다.

1. **High-pass filter**: 저주파 진동·에어컨 웅웅거림을 줄인다.
2. **Noise suppression**: 일정한 팬·에어컨 소음을 줄인다. WebRTC NS 또는 RNNoise 계열을 검토한다.
3. **VAD**: 말하는 구간과 무음 구간을 구분한다.
4. **AGC**: 거리 변화에 따른 음량을 보정한다. 과도하면 배경 소음도 키우므로 제한한다.
5. **Echo cancellation**: PC 스피커로 Codex 음성이 나올 때 재생음이 마이크로 재입력되는 것을 줄인다.
6. **Beamforming**: 마이크 배열이 있을 때 말하는 방향의 신호를 강조한다.

단일 아날로그 마이크에서는 소프트웨어만으로 5m·10m 성능을 보장하기 어렵다. 원거리 성능은 마이크의 지향성, 마이크 배열, 설치 방향, 방의 잔향과 SNR이 더 중요하다. 따라서 원본 입력과 처리 후 입력을 같은 조건에서 A/B 비교한다.

## 7. 구현 시 주의점

- Windows 음향 효과, ChatGPT 음성 처리, companion의 DSP를 동시에 켜면 이중 처리로 음성이 왜곡될 수 있다.
- 자동 게인과 노이즈 억제를 wake-word 감지 경로와 본문 음성 인식 경로에 동일하게 적용하지 않는다.
- wake 감지는 낮은 지연과 낮은 오인식이 우선이고, 본문 전사는 문장 정확도가 우선이다.
- `고고`는 인식 성공만으로 즉시 전송하지 말고, 발화 끝·현재 입력 존재·Voice 활성 상태를 함께 확인한다.
- `고스톱`은 모든 활성 상태에서 처리하는 fail-safe 명령으로 둔다.
- 노이즈 캔슬링 전후에 `False wake`와 `False send`가 증가하지 않는지 별도로 검증한다.

## 8. 1차 개발 권장 순서

1. DSP 없이 거리·소음·SNR·명령 성공률 기준값을 수집한다.
2. Windows 기본 음향 효과를 끈 상태와 켠 상태를 비교한다.
3. 소프트웨어 noise suppression만 추가해 A/B 비교한다.
4. VAD와 명령 끝점 감지를 추가한다.
5. 스피커 재생이 있는 경우 echo cancellation을 추가한다.
6. 최종적으로 wake·gogo·gostop 상태 머신에 연결한다.

현재 마이크 모델이 확인되지 않았으므로, 첫 시험은 마이크와 입 사이의 30cm 기준 음량을 정한 뒤 거리별로 SNR과 명령 성공률을 측정하는 방식이 적절하다.
