# 보이스톡 커맨드 기능 명세서

## 1. 문서 목적

Windows용 Codex 데스크톱 작업 중 마이크 버튼을 직접 누르지 않고, 사용자가 정한 웨이크워드와 음성 커맨드로 보이스 입력을 시작하고 전송하는 로컬 companion 프로그램을 정의한다.

이 기능의 목표는 다음과 같다.

- 지정한 별칭을 들으면 대기 상태에서 음성 입력을 시작한다.
- ChatGPT/Codex 데스크톱 창을 활성화하고 Voice 버튼을 UI 자동화로 누른다.
- 사용자가 말한 “오버”를 발화 종료 및 전송 커맨드로 처리한다.
- “스톱”은 현재 입력을 중지하고, “그만”은 보이스 제어를 종료한다.
- 화면 크기나 창 위치가 바뀌어도 고정 좌표가 아닌 UI 요소 탐색으로 동작한다.
- 설치 가능한 VS Code/Codex 보조 플러그인 패키지로 배포한다.

## 2. 용어

- 웨이크워드: 프로그램을 깨우는 별칭. 기본값은 “챗GPT”이며 사용자가 변경할 수 있다.
- 오버: 현재 음성 발화를 끝내고 전송하는 음성 커맨드.
- 스톱: 현재 음성 입력을 중단하는 커맨드.
- 그만: 보이스 제어를 종료하고 웨이크워드 대기 상태로 돌아가는 커맨드.
- companion: ChatGPT/Codex 데스크톱 외부에서 실행되며 Windows 접근성 자동화로 앱을 제어하는 보조 프로그램.
- UI Automation: 화면 좌표가 아니라 접근성 트리의 이름, 역할, 컨트롤 패턴을 사용해 버튼을 찾고 Invoke 동작을 실행하는 Windows 자동화 방식.

## 3. 범위

### 포함

1. Windows 트레이 상주 companion 앱
2. 설정 가능한 웨이크워드
3. 로컬 음성 인식 기반 커맨드 판별
4. ChatGPT/Codex 데스크톱 창 탐색 및 활성화
5. Voice 버튼과 전송/중지 버튼의 UI Automation 탐색
6. 오버, 스톱, 그만 커맨드 처리
7. 실행 상태 오버레이 또는 트레이 상태 표시
8. 로그, 오류 안내, 재시도
9. VS Code 확장 또는 Codex 플러그인과 companion 간 IPC
10. 설치 패키지와 제거 방법

### 제외

- ChatGPT 데스크톱 내부 코드를 수정하는 기능
- 공식 OpenAI 음성 입력 API가 제공된다고 가정한 직접 오디오 주입
- 화면 좌표를 영구 저장하는 방식
- 기본값으로 음성 원본을 저장하거나 외부 서버에 업로드하는 기능
- 사용자의 승인 없이 메시지를 전송하는 일반 자동화

## 4. 사용자 흐름

1. 사용자가 companion을 실행한다.
2. 프로그램은 웨이크워드를 듣는 대기 상태가 된다.
3. 사용자가 “챗GPT”라고 말한다.
4. 프로그램은 ChatGPT/Codex 데스크톱 창을 찾고 앞으로 가져온다.
5. UI Automation으로 Voice 또는 마이크 버튼을 찾아 Invoke한다.
6. 사용자가 질문을 말한다.
7. 사용자가 “오버”라고 말한다.
8. 프로그램은 발화를 종료하고 전송 버튼을 찾아 Invoke한다.
9. 전송이 완료되면 다시 웨이크워드 대기 상태가 된다.

## 5. 상태 머신

| 상태 | 설명 | 다음 상태 |
|---|---|---|
| IDLE | 웨이크워드 대기 | WAKE_DETECTED |
| WAKE_DETECTED | 웨이크워드 인식 | ACTIVATING |
| ACTIVATING | 데스크톱 창 활성화 및 Voice 버튼 탐색 | LISTENING 또는 ERROR |
| LISTENING | 사용자 발화 수집 | SENDING, STOPPED, IDLE |
| SENDING | 발화 종료 및 전송 버튼 실행 | IDLE 또는 ERROR |
| STOPPED | 입력 중지 후 결과 대기 | IDLE |
| ERROR | 실패 원인 표시 및 재시도 | IDLE |

## 6. 커맨드 규격

| 기본 커맨드 | 동작 | 설정 가능 여부 |
|---|---|---|
| 챗GPT | 웨이크업 및 Voice 시작 | 별칭 변경 가능 |
| 오버 | 음성 입력 종료 및 전송 | 변경 가능 |
| 스톱 | 현재 입력 중지 | 변경 가능 |
| 그만 | 제어 종료 및 대기 복귀 | 변경 가능 |

커맨드가 일반 문장 안에 포함된 경우에는 오인식을 줄이기 위해 발화 끝부분의 커맨드만 명령으로 인정한다. 커맨드 인식 후에는 해당 커맨드 단어가 실제 질문 내용으로 전송되지 않도록 제거한다.

## 7. UI Automation 동작

1. 대상 프로세스와 창 제목을 기준으로 ChatGPT/Codex 데스크톱 창을 찾는다.
2. 창이 최소화되어 있으면 복원하고 포커스를 준다.
3. 접근성 트리에서 Button 컨트롤을 검색한다.
4. Name, AutomationId, ControlType, 지원 패턴을 조합해 Voice 버튼을 식별한다.
5. InvokePattern을 우선 사용하고, 지원되지 않을 때만 제한적인 보조 방법을 사용한다.
6. 창 크기 변경, 분할, 테마 변경 뒤에는 요소를 다시 검색한다.
7. 버튼을 찾지 못하면 화면 좌표를 임의로 클릭하지 않고 오류 상태와 복구 방법을 표시한다.

## 8. 음성 및 개인정보

- 웨이크워드 감지는 로컬 처리를 우선한다.
- 음성 원본은 기본적으로 저장하지 않는다.
- 음성 인식 엔진, 언어, 감도, 오인식 방지 시간은 설정 가능하게 한다.
- 사용자가 명시적으로 동의하지 않는 한 음성 데이터와 질문 내용은 로그에 기록하지 않는다.
- 트레이 메뉴에서 마이크 감지 활성화 여부를 즉시 확인할 수 있어야 한다.

## 9. 구성 요소

### Companion 앱

- Windows 트레이 프로세스
- 웨이크워드 및 커맨드 감지
- 대상 창 탐색
- UI Automation 실행
- 상태 표시와 설정 관리

### VS Code 확장 또는 Codex 플러그인

- companion 실행/종료
- 커맨드와 상태 표시
- 설정 화면 제공
- IPC 연결 상태 표시
- 로그 열기 및 진단 정보 제공

플러그인은 companion을 호출하고 상태를 교환하는 제어 계층이다. ChatGPT/Codex 데스크톱의 공식 내부 Voice API를 직접 호출하는 플러그인으로 정의하지 않는다.

## 10. IPC

- 로컬 WebSocket, named pipe 또는 localhost HTTP 중 하나를 선택한다.
- 메시지에는 version, type, timestamp, requestId를 포함한다.
- 주요 이벤트는 wakeDetected, voiceStarted, sendRequested, stopped, completed, error이다.
- 인증되지 않은 외부 연결은 거부한다.
- companion이 종료되면 플러그인은 오프라인 상태를 표시한다.

## 11. 실패 처리

- ChatGPT/Codex 창을 찾지 못함: 앱 실행 또는 포커스 방법 안내
- Voice 버튼을 찾지 못함: UI 접근성 트리 진단 로그 제공
- 전송 버튼을 찾지 못함: 입력 종료 후 재검색, 실패 시 사용자 확인 요청
- 웨이크워드 오인식: 감도 조절과 쿨다운 제공
- 네트워크 또는 음성 인식 실패: 자동 재시도 후 대기 상태 복귀
- 동일 명령 반복: 한 번만 처리하고 중복 전송 방지

## 12. 설정 예시

| 설정 | 기본값 |
|---|---|
| wakeWord | 챗GPT |
| sendCommand | 오버 |
| stopCommand | 스톱 |
| exitCommand | 그만 |
| language | ko-KR |
| localOnlyWakeDetection | true |
| saveAudio | false |
| commandCooldownMs | 1200 |

## 13. 보안 및 안전 요구사항

- 자동 전송은 오버 커맨드가 명확히 인식된 경우에만 수행한다.
- 사용자가 원하면 전송 전 확인 모드를 켤 수 있어야 한다.
- 민감한 입력을 다루는 동안 트레이 상태를 표시한다.
- 로그에는 토큰, 인증정보, 음성 원본, 질문 전문을 남기지 않는다.
- 앱 종료 시 마이크 감지와 IPC 서버를 함께 종료한다.

## 14. 설치 및 플러그인 요구사항

1. companion 실행 파일 또는 설치 스크립트를 제공한다.
2. VS Code 확장을 VSIX로 패키징한다.
3. 확장 설치 후 companion 경로와 설정 파일 위치를 지정한다.
4. 설치 직후 진단 명령으로 IPC와 UI Automation 연결을 검사한다.
5. 제거 시 확장, companion 자동 시작 등록, 설정을 각각 선택적으로 제거한다.

## 15. 검수 기준

- 창 위치를 바꿔도 Voice 버튼을 찾아 시작할 수 있다.
- 창 크기를 반으로 줄여도 좌표 오류 없이 동작한다.
- 웨이크워드 후 Voice 버튼이 한 번만 눌린다.
- “오버” 후 전송이 한 번만 실행된다.
- “스톱”은 전송하지 않고 입력을 중지한다.
- “그만”은 대기 상태로 복귀한다.
- 창이 닫혔거나 버튼이 없을 때 안전하게 실패한다.
- 음성 원본이 기본 저장되지 않는다.
- VS Code 확장에서 companion 상태를 확인할 수 있다.

## 16. 구현 순서

1. 현재 VS Code companion 구조를 이 명세에 맞게 정리한다.
2. 웨이크워드와 커맨드 상태 머신을 구현한다.
3. Windows UI Automation 탐색기를 구현한다.
4. ChatGPT/Codex 창에서 Voice, Stop, Send 요소를 진단한다.
5. 실제 앱을 대상으로 수동 검수한다.
6. IPC와 VSIX 명령을 연결한다.
7. 설치 패키지와 복구 절차를 작성한다.

## 17. 현재 결론

이 기능은 “공식 데스크톱 플러그인이 Voice API를 직접 호출하는 구조”가 아니라, 로컬 companion이 음성을 감지하고 Windows UI Automation으로 데스크톱 UI를 제어하는 구조로 구현한다. 공식 내부 API가 공개되면 UI Automation 계층을 API 어댑터로 교체할 수 있도록 인터페이스를 분리한다.

작업 완료 알림이나 결과 자동 낭독은 이 플러그인의 요구사항이 아니다. 이는 Codex 데스크톱 앱 자체의 설정 가능 여부로 별도 확인해야 한다.
